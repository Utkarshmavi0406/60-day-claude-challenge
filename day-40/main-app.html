System Prompt Design

The assistant's brain is a single production system prompt (shown in full below) built around four decisions: (1) it is explicitly framed as decision support, never a final authority, so every report reminds the analyst that human review and policy/compliance checks come first; (2) it collects facts through one focused question at a time rather than a giant form, which mirrors how a real underwriter conversation flows and lets the assistant adapt follow-ups to prior answers; (3) it defines a strict, parseable output contract — every final report starts with the literal marker ===FINAL_REPORT=== so the frontend can reliably detect "this message is a report" and render it as a structured card instead of a chat bubble; (4) it hard-codes fair-lending guardrails (ECOA/Regulation B protected classes, no zip-code proxying, no SSNs) directly into the constraints section rather than trusting the model to infer them.

UI Decisions

  • Conversational input, structured output. Input is free-text chat (matches how an analyst actually knows the applicant's details), but the moment the model emits the ===FINAL_REPORT=== marker, the frontend switches rendering modes and produces a formatted report card with a color-coded verdict pill (green/amber/red) instead of another chat bubble.
  • Progress stages in the sidebar give the analyst a sense of where they are in the interview even though the underlying flow is a plain conversation, not a rigid wizard — stages advance heuristically as topics are covered.
  • Institutional visual language (navy, restrained color, monospace numerals for figures like DTI% and risk score) was chosen deliberately to read as a banking tool rather than a consumer chatbot.
  • Graceful failure states for a missing/invalid API key, network failures, and rate limits are surfaced as an inline banner rather than a silent failure or raw error dump.

Ideas for Future Extensions

  • Tools: a real deployment would call a credit bureau API and internal loan-origination system as tools instead of asking the analyst to type figures by hand, with the model only asking about anything the systems can't supply.
  • Memory: persisting past reports per applicant would let the copilot flag "this applicant was declined 90 days ago for X" automatically on a repeat application.
  • Multi-step workflows: routing a "Refer" verdict into a second, senior-underwriter-facing conversation thread, or triggering an automated adverse-action-notice draft on Decline, would turn this from a single-session assistant into a full underwriting pipeline stage.
