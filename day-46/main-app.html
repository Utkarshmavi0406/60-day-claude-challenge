Agent Roster & Responsibilities

How the stop-check governs information flow between rounds

Each round, Evaluator scores the current draft fresh (it never sees its own prior score, only the code). Critic receives the Evaluator's report and pinpoints concrete issues. Safety Monitor independently checks the same draft for dangerous patterns. Memory Manager compresses the full round history into a short brief — what's fixed, what recurs, what's untried — specifically so Improver doesn't re-litigate settled issues or oscillate between two fixes. The Stop Check runs after Memory Manager and before Improver is even called: if it fires, Improver is skipped entirely and control passes to Final Reviewer instead.

Architecture Overview

How the loop actually works

  • Round 0: Planner → Executor produce the first real draft (2 API calls, no scoring yet)
  • Each round after: Evaluator → Critic → Safety Monitor → Memory Manager, all live calls, all feeding a running history array
  • Stop Check runs in fixed order: plateau → threshold → hard cap — first one to fire wins and is logged
  • If no stop condition fires, Improver is called with the full context and the loop repeats
  • Final Reviewer runs exactly once, after the loop ends, regardless of which condition stopped it

Extension ideas

  • Add a Tester agent that actually executes the generated code against sample inputs, not just reads it
  • Let Safety Monitor have veto power — force an extra Improver pass if it flags, independent of the score
  • Persist round history across sessions so repeated runs on similar tasks start from prior learnings
  • Add a second Critic with an adversarial prompt (find ways the code could still fail) for a stronger signal

Further prompts for building more advanced autonomous systems

  • "Design a stop condition that also accounts for diminishing API-cost-per-point-gained, not just score plateau."
  • "Add a Debate agent that argues against the Critic's findings before Improver acts on them."
  • "Turn this single-track pipeline into a fan-out/fan-in system with 3 parallel Improver attempts, judged by a Selector agent."
  • "Add a human-in-the-loop approval gate before Final Reviewer's output is treated as done."
